# L3 模型 + 优化层方案

## 1. 核心原则：两段式，不端到端

```
第一段  信号生成：输出 每只标的的 预期收益 或 排序分
第二段  权重优化：在约束下解出权重
```

**为什么必须拆开**：均值方差优化器对预期收益 μ 极度敏感，是臭名昭著的 *error maximizer* —— 微小 μ 误差会被放大成极端权重（全押一只）。端到端模型学出来的 μ 误差更大，结果更糟。

## 2. 三档递进（每档必须跑完并记录指标，才能进下一档）

### 基线0：等权
```
w_i = 1/N
```
最低门槛。等权组合经常打败复杂模型，这是现实。

### 基线1：风险平价 / 最小方差
```
min  wᵀ Σ w            (最小方差)
或   w_i ∝ 1/σ_i        (逆波动率，风险平价简化版)
```
用 Ledoit-Wolf 收缩协方差。

### 基线2：动量 + 逆波动率（经典 ETF 轮动）
```
score_i = mom_12_1_i / vol_60_i
选 score 排名前 K 只，按 1/vol_60 加权
```
**这是真正的对手。** 学术与实盘都显示它极难被超越。

> 门槛设定：基线2 的 Sharpe 记为 `S_baseline`。后续模型必须 `S_model > S_baseline × 1.1` 才保留。

### 基线2 达标即可停止的决策点（避免默认往下做ML）

基线0/1/2 全部跑完后，**先做一次是否继续的判断，不要默认接着做模型A/B**：

| 情形 | 建议动作 |
|---|---|
| 基线2 的 Sharpe ≥ 1.0，且换手率/回撤在可接受范围 | **直接采用基线2 作为最终决策规则，项目到此交付**——"动量+逆波动率"本身就是一条纪律化、可执行、有历史证据支撑的规则，不需要再叠加ML复杂度和过拟合风险 |
| 基线2 的 Sharpe 明显不够（如 < 0.8）或回撤/换手不可接受 | 才进入 §3~§4 模型A/B，且要清楚：学术界大量证据显示"动量+逆波动率"这类简单规则很难被稳定打败，进入模型阶段前先接受这个预期 |
| 时间/精力有限，且基线2 结果"凑合但不惊艳" | 优先把省下来的时间投入 04-backtest.md 的稳健性测试和 05-risks.md 的监控体系建设，这两项对"能不能真的照着做交易"的价值 > 多试一个模型 |

**原因**：00-overview.md 已经把项目价值定位为"纪律化的权重决策 + 风险监控工具"而非"alpha 生成器"（见 00-overview.md §7）。如果基线2 已经能满足这个定位，模型A/B 就是可选的加分项，不是必需路径——避免"顺便试试ML"变成事实上的隐性必选项，拖长交付周期又不一定有收益。

## 3. 模型A：收益预测（GBDT）

| 项 | 选择 |
|---|---|
| 模型 | LightGBM（回归 or 排序） |
| 目标 | 下期收益 / 下期收益的横截面 rank |
| 标签 | `forward_ret_20d`（未来 20 日收益） |
| 特征 | L2 全部因子（横截面标准化后） |
| 样本权重 | 近期样本加权（半衰期 250 日） |
| 输出 | 每标的 score |

**推荐直接预测 rank 而非绝对收益**：
- 绝对收益信噪比 < 1%，模型易过拟合
- Rank 只用相对信息，鲁棒得多
- 优化器只关心排序，不关心绝对水平

### 防过拟合措施
| 措施 | 参数 |
|---|---|
| Walk-forward | 训练 750 日 / 验证 120 日 / 测试 60 日 |
| 早停 | 验证集 IC 连续 5 轮下降 |
| 正则 | `num_leaves ≤ 31`，`min_data_in_leaf ≥ 50` |
| 特征数 | ≤ 30，先做重要性筛选 |
| 特征抽样 | `feature_fraction = 0.7` |
| 禁止随机切分 | 时序必须按时间 |

### 替代模型
- 线性：Ridge / Lasso（可解释性强，常打败复杂模型）
- 树：XGBoost / CatBoost
- 深度：LSTM / Transformer（**最后再试，容易过拟合**）

## 4. 模型B：Black-Litterman（融合观点）

把模型A 的 score 转成 view，与市场均衡收益融合：

```
π = δ Σ w_mkt                              # 市场均衡隐含收益
Q = 模型A 预测的收益向量                     # view
P = 选择矩阵                                # 哪些标的被 view 覆盖
Ω = τ P Σ Pᵀ                                # view 不确定性
μ_BL = [(τΣ)⁻¹ + PᵀΩ⁻¹P]⁻¹ [(τΣ)⁻¹π + PᵀΩ⁻¹Q]
```

**优势**：模型只提供"偏移量"，均衡收益兜底，避免极端权重。
**τ** 建议 0.05~0.1，`Ω` 越大表示越不信任模型。

## 5. 权重优化器

```python
# 输入: mu (预期收益), Sigma (收缩协方差), 约束参数
# 输出: w (权重)
minimize    -wᵀ μ + λ · wᵀ Σ w
s.t.        Σ w_i = 1                    # 满仓
            0 ≤ w_i ≤ 0.10               # 单标的上限
            Σ_{i∈行业j} w_i ≤ 0.30       # 单行业上限
            ||w - w_prev||₁ ≤ 0.30       # 换手约束
            w_QDII = 0 if premium > 3%   # 跨境约束
```

| 变体 | 目标 |
|---|---|
| max Sharpe | max (wᵀμ − r_f) / √(wᵀΣw) |
| min 波动 | min wᵀΣw |
| max Calmar | max 年化收益 / \|MaxDD\| |
| 风险平价 | 各标的风险贡献相等 |

工具：`cvxpy`（凸问题，全局最优）或 `PyPortfolioOpt`（封装好）。

### 反向优化：为何要加 λ
- 纯 max Sharpe → 权重极端集中，实盘不可执行
- λ 惩罚项 → 权重向分散靠拢，更稳
- λ 用验证集调，不要用测试集

### 小资金个人账户的成本假设需要单独校准

优化器约束里的 `||w - w_prev||₁ ≤ 0.30`（换手约束）和单标的/单行业上限，其设计初衷是**限制冲击成本和流动性风险**——这个假设对机构资金（单笔订单可能占当日成交额的显著比例）成立，但对个人小资金账户，实际成本结构不同：

| 成本项 | 机构大资金 | 个人小资金账户 |
|---|---|---|
| 冲击成本（`α·√(order_amt/daily_amt)`） | 主导项，订单会推动价格 | 通常可忽略——几万到几十万的单笔订单相对ETF日成交额（常见 5000万+）占比 < 0.5%，冲击几乎为0 |
| 佣金 + 买卖价差 | 相对次要（大资金摊薄固定成本） | **主导项**——每次调仓的固定佣金（如有最低5元/笔）+ 价差（0.1%~0.5%）在小资金下占比更高 |
| 换手约束的真实作用 | 控制冲击成本和市场影响 | 更多是控制"佣金笔数×价差"的累计磨损，而非价格冲击 |

**校准建议**：
1. 04-backtest.md 里的冲击成本项（α≈0.1）对个人账户可以直接设为 0 或极小值，不要照抄机构参数
2. λ 的调优目标从"避免冲击成本"转为"避免过度频繁的小额调仓"——如果模型每月建议的权重变动很小（如<2%），个人账户实际执行时这笔调整可能连佣金都覆盖不了，应该设置一个"最小调仓幅度"门槛（如单标的权重变化<3%则不执行），这个门槛在优化器约束里目前没有体现，建议在实盘执行层补充
3. `||w - w_prev||₁ ≤ 0.30` 这条约束对个人账户仍然有效，但理由变成"避免交易过于频繁产生的佣金磨损"，不是"避免冲击成本"——理解这个差异有助于后续调参不跑偏方向

## 6. 模型C：端到端（不推荐起步用）

直接把权重作为输出，损失函数 = 负 Sharpe。用可微优化层（cvxpylayers）或强化学习。

**问题**：参数少、信噪比低、极易过拟合，且黑箱不可解释。
**建议**：做完 A/B 且确认有增量后再试，只作为对比。

## 7. 消融实验（必须做）

| 实验 | 目的 |
|---|---|
| 去掉所有因子 → 等权 | 验证因子体系是否有用 |
| 只用动量因子 | 对比基线2 |
| 逐个加因子组 | 定位哪组因子有效 |
| 换模型（LightGBM → Ridge） | 验证不是模型在拟合噪音 |

**若消融后没有一组因子带来提升 → 因子体系无效，回 L2 重做，别调模型。**

## 8. 迭代闭环（原 Step4 的修正版）

```
原: 预测结果 vs 实际收盘  →  ❌ 权重没有"实际收盘"可对照
改: walk-forward 回测 → 绩效归因 → 反馈到 L2 特征 / L3 模型
```

闭环反馈路径：

| 观察 | 修正动作 |
|---|---|
| 因子 IC 衰减 | 缩短回看窗口 / 剔除因子 |
| 组合偏离基线过多 | 增大 λ 或缩小 τ 的 view 权重 |
| 换手率过高 | 收紧换手约束 / 加漂移带 |
| 回测好实盘差 | 检查成本假设 / 信息泄漏 |
| 某类资产持续跑输 | 检查标的池，剔除 |
