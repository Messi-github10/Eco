# ETF/QDII 组合权重辅助决策系统 — 方案总览

## 0. 目标重述

原始需求：预测 ETF / QDII 的持仓权重，与实际收盘结果对比，迭代模型。

**修正后的目标**：把"预测权重"拆成两段式流水线，而不是一个端到端模型。

```
信号层(预期收益/风险) → 优化器解权重 → walk-forward 回测 → 归因 → 迭代
         L2/L3                L4              L5
```

产出物：每月一组目标权重（每只 ETF 配多少 %），附带风险指标与回测证据。

## 1. L0 参数（先定死，否则全部返工）

### 1.1 标的池筛选规则（可直接执行，避免"等选好清单再动工"）

一期只做 A 股 ETF，按以下规则**自动生成清单**，不需要手工挑选：

```
候选池 = 全市场 ETF（fund_etf_spot_em）中满足：
  1. 上市满 2 年（list_date <= today - 2年）  —— 剔除新发基金，数据不够回测
  2. 近 60 个交易日日均成交额 > 5000 万元      —— 流动性门槛
  3. 最新规模（aum） > 5 亿元                  —— 剔除迷你基金，防清盘风险
  4. 剔除 QDII / LOF 中的跨境品种（is_cross_border = False） —— 一期范围
  5. 按 track_index 去重：同一指数只保留规模最大的1只  —— 防止同质ETF挤占标的池

排序后取前 20~40 只（若不足20只，放宽 aum 门槛到 3 亿；若仍不足，放宽成交额门槛）
覆盖要求：宽基（沪深300/中证500/科创50等）+ 至少5个一级行业，避免行业过度集中
```

**产出**：`config/universe.yaml`，字段包含 code / name / track_index / 行业分类 / 入选时的三项指标值（留痕，便于复查规则是否合理）。

**复审频率**：每季度重跑一次筛选规则，若某标的跌出门槛（如规模萎缩/成交萎缩），下一期调仓时逐步移除，不做临时剔除（避免规则被拍脑袋绕过）。

| 项 | 起步值 | 备注 |
|---|---|---|
| 标的池 | 20~40 只高流动性 ETF（见 §1.1 筛选规则） | 宽基 + 行业，日成交额 > 5000 万 |
| 调仓频率 | 月频 | 周频列二期 |
| 基准 | 等权组合 + 沪深300 | 两个都要，缺一不可 |
| 目标函数 | max Sharpe | 备选：min 波动 + 收益下限 |
| 单标的权重 | ≤ 10% | 硬约束 |
| 单行业权重 | ≤ 30% | 硬约束 |
| 单期换手 | ≤ 30% | 控制成本 |
| 做空 | 禁止 | |
| 权重和 | = 1 | 满仓 |
| QDII 折溢价 | > 3% 禁买 | 跨境专属约束 |
| QDII 限购期 | 剔除 | 无法建仓 |

## 3. 里程碑（一期，A股ETF）

> 以下为"顺利情况下"的乐观估，现实排期建议乘 1.5~2 倍（IC/回测任一环节不达标需退回上一层重做）。

| # | 交付 | 乐观估 | 验收标准 |
|---|---|---|---|
| M1 | 取数 + 落库 | 2~3 天 | 20~40 只 ETF × 5 年日频，复权对账通过，双源交叉验证误差 < 0.5% |
| M2 | 因子 + 看板 | 2~3 天 | Streamlit 可查看全部标的的指标 |
| M3 | 回测引擎 | 5~7 天 | 含成本、约束、walk-forward，反过拟合checklist通过 |
| M4 | 基线 0/1/2 | 2 天 | 记录 Sharpe 作为门槛 |

### M1~M4 完成后的决策关卡（不是自动进入M5）

M4 交付后，**先停下来做一次决策**，而不是默认往下走 ML：

```
若 基线2（动量+逆波动率）的 Sharpe/Calmar 已经达到你的预期
   → 直接采用基线2 作为最终决策规则，项目在此交付
   → "纪律化权重决策 + 风险监控"本身就是完整可用的产品，不需要ML兜底

若 基线2 明显不够（比如 Sharpe < 1，或换手率/回撤不可接受）
   → 才进入 M5，且要清楚 M5 打败基线2 的概率本身不高（见 03-model.md §1）
```

这一关卡的意义：**避免把"顺便试试ML"当成必选项**，M4 已经交付"数据管道+因子体系+回测证据+纪律化规则"这四项本项目最确定的价值（见 05-risks.md §8）。

## 4. M5（二期，非本期必需）

| # | 交付 | 乐观估 | 验收标准 |
|---|---|---|---|
| M5 | ML 模型 | 5 天+（现实估 10~15 天+） | 必须打超基线2×1.1，否则不保留 |

M5 单独列为二期而非一期收尾，原因：
- 因子 IC 检验（02-factors.md §4）没过就要退回 L2 重做，不能直接拿因子喂模型
- 消融实验（03-model.md §7）任一环节不通过，模型不成立
- 这部分工作量和不确定性都显著高于 M1~M4，混在一期时间线里会拖累整体交付节奏

## 5. 明确不做（避免范围蔓延）

- 不做日内 / 高频
- 不做个股选择
- 不做成分股权重（指数调仓）预测 —— 需 PCF，AKShare 无接口
- 不接实盘下单
- QDII 一期不做，二期再加

## 7. 一句话预期管理

数据层、指标、优化、回测 —— 都能做，且能做扎实。
**ML 能不能超越简单动量基线，是唯一真正的未知数。** 项目价值应定位为"纪律化的权重决策 + 风险监控工具"，而非"alpha 生成器"。
