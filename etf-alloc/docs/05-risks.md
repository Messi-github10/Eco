# L5 风险、合规与监控

## 1. 数据源风险

| 风险 | 影响 | 对策 |
|---|---|---|
| AKShare 接口随时改名/失效 | 取数中断 | 锁版本 + 冒烟测试 + 多源降级 |
| 网页结构变化 | 字段错位 | 落库前做 schema 断言 |
| 限频/反爬 | 批量拉取失败 | 间隔 + 指数退避重试 |
| 单源数据错误 | 结论错误 | 关键字段交叉验证（东财 vs 新浪） |
| 数据源停止维护 | 项目瘫痪 | 核心表自建，AKShare 仅作补充 |

**关键认知**：AKShare 官方明确声明数据**仅用于学术研究**。生产级使用需自建数据管道或采购商业数据源（Wind / 聚宽 / Tushare Pro）。

## 2. 方法论风险

| 风险 | 说明 | 对策 |
|---|---|---|
| **信息泄漏** | 季报按报告期对齐 → 回测虚高 | 全部按 `publish_date` 对齐 |
| **幸存者偏差** | 标的池只含现存 ETF | 纳入已退市标的 |
| **过拟合** | 参数多、样本少 | walk-forward + 消融实验 |
| **error maximizer** | μ 误差被优化器放大 | 只预测 rank + BL 融合 + λ 正则 |
| **协方差奇异** | N 大 T 小 | Ledoit-Wolf 收缩 |
| **复权错误** | 收益率全错 | 手工对账 3~5 只标的 |
| **多重检验** | 试了 100 个因子挑最好的 | 报告需做 FDR / 样本外验证 |
| **前视偏差** | 用了未来数据算因子 | 所有因子 t 日只用 t 及之前 |
| **时间对齐错误** | QDII 时区差 | 统一 Asia/Shanghai + 公布日对齐 |
| **样本量不足导致IC统计不显著** | 标的池仅20~40只，截面窄；回测覆盖期<3年时IC置信区间很宽，`\|IC\|>0.03`很容易是噪音凑出来的点估计，不代表因子真实有效 | IC检验必须同时报告 t统计量/p值，且做FDR多重检验校正；候选因子须在样本外复验仍显著才采纳；回测覆盖期建议≥5年才正式采信IC结论（详见 `02-factors.md` §4.1/§4.2） |

## 3. 结论可靠性分级

| 结论类型 | 可信度 | 说明 |
|---|---|---|
| 数据统计描述 | 高 | 直接可验证 |
| 因子 IC 显著性 | 中 | 需样本外确认 |
| 回测绩效 | 中低 | 依赖成本与约束假设 |
| 实盘可复制性 | 低 | 需实测验证 |
| ML 带来的增量 | 最低 | 多数情况下不显著 |

**原则**：对外表述时按此分级措辞，不要用回测绩效承诺未来收益。

## 4. 合规与安全

- AKShare 数据仅学术用途，**商业使用需自行评估法律风险**
- 本项目定位为**个人研究工具**，不含投资建议输出
- 不接入实盘自动下单（一期）
- 不对外分发数据（AKShare 数据源有各自版权）
- 不存储任何非公开数据或个人隐私数据
- 若输出给他人看，须附风险提示

## 5. L5 监控体系

### 5.1 日常监控（每日）

| 监控项 | 阈值 | 动作 |
|---|---|---|
| 取数成功率 | < 95% | 告警 + 人工介入 |
| 数据缺失 | 交易日缺失 | 补拉 |
| 异常收益 | \|ret\| > 15% | 复核 |
| 折溢价 | > 5% | 标记，检查是否需禁买 |
| 份额突变 | > 50% | 复核拆分/合并 |

### 5.2 模型监控（月度）

| 监控项 | 阈值 | 动作 |
|---|---|---|
| 因子 IC 滚动均值 | < 0（持续 3 月） | 剔除该因子 |
| 模型 IC vs 训练期 | 下降 > 50% | 重训或降级到基线 |
| 实际权重 vs 目标权重 | 偏离 > 5% | 检查执行 |
| 组合换手率 | > 40%/月 | 收紧约束 |
| 滚动 12 月 Sharpe | 低于基线 | **降级回基线2** |

### 5.3 降级机制（必须预设）

```
模型失效 → 自动降级到基线2（动量+逆波动率）
基线2 也失效 → 降级到等权
```
**这是保命设计**：模型不可能永远有效，关键是失效时能识别并退回。

## 6. 事前风险提示（写在项目 README）

1. 本项目为**研究工具**，非投资建议，不构成任何收益承诺
2. 历史回测表现**不代表**未来收益
3. ETF/QDII 存在市场风险、流动性风险、折溢价风险、汇率风险
4. 跨境 ETF 存在**限购、高溢价、跟踪误差大**等特有风险
5. 模型存在**失效风险**，需持续监控
6. 数据来自公开渠道，准确性由数据源决定
7. 使用者自行承担全部投资决策后果

## 8. 项目成功的定义（现实版）

**失败定义**：回测 Sharpe 很高，但实盘不赚钱。

**成功定义**（按优先级）：
1. 拥有一个**可复现、无泄漏**的数据与回测管道
2. 拥有一套**经过检验**的因子体系（有 IC 证据）
3. 拥有一个**纪律化的权重决策流程**，替代拍脑袋
4. 拥有**风险监控与自动降级**能力
5. 模型能否产生超额 —— **是 bonus，不是前提**

第 1~4 项是本项目真正确定能交付的价值。
